# 多机器人后台路径规划验收

2026-10-16，`20261016-worker-1`。本轮只改多机器人页的耗时路径搜索和任务状态呈现，保留两套已确认的场景、原机器人控制器、1ms物理步长、接触与碰撞门槛。发布沿用仓库既有 GitHub Pages 自动流程，部署前需通过该流程的验证。

## 实现与边界

原先的分段适配器只在完整候选之间交还事件循环；G1 的单个候选仍可能占住主线程，候选多时容易看起来卡死。现在每台参与机器人用独立 Web Worker 计算候选路线，页面只提交快照和轮询结果。后续每根圆管也经过相同入口，不是只把第一根移出主线程。

主世界不安装 worker 的 `qpos/qvel` 或预测接触，只接受明确白名单内的已验证路径和控制命令。原主线程仍运行真实物理、阶段安全检查与少量落桌反馈逆解。各物理世界在待规划屏障中一起等待，以保留同一时钟与路径输入一致性；这不承诺机器人在规划期间仍运动、任何位置都可达、所有逆解均离开主线程或恒定帧率。

保留普通任务10秒、G1圆管30秒的累计计算片段预算（不计候选间主动调度等待，不能视为操作系统精确CPU时间），另有90秒后台墙钟看门狗。停止/复位直接终止对应 worker；generation、job ID、编译模型、物体和控制状态匹配检查拒绝过期结果。不支持或加载失败时明确报错，不偷偷回退到主线程搜索。

本轮后台实现的回归曾发现：随机摆放更新布局但保留原模型的body/joint顺序；worker若按新seed重新编译，会把原始状态数组映射到错误圆管。现快照明确区分原始场景、实际编译场景/seed和当前布局，先生成同一编译顺序再还原布局；`xpos/xquat`也保留源采样的准确值。该问题是本轮异步改造中发现的回归，不是对旧版卡顿根因的替代解释。

界面仅显示“后台规划/后台检查路径”，没有新增当前圆管序号、候选数量或等待秒数。原来的已归类件数和任务进度保留。

## 当前专项证据

最终[完整圆管物理回归](pipes-physical-compiled-model-final.json)实际运行1446.0603秒，FULL模式8/8场景、72/72根通过，源码冻结。包括连续两次随机布局的三机分类（24+24根）、R1/G1/C5单独执行（各8根），以及停止、不可达与随机复位3个恢复场景；另有300组基础布局检查。原1ms步长、真实双指接触/抬升、邻管受力、关节行程/速度及最后3秒稳定落桌检查保留，没有改写生产预算。这是固定测试布局的通过记录，不表示任意随机位置或任意设备都能成功。

- [Worker契约](contracts-final.json)：24项实际运行，涵盖原始运动链、完整计划/命令逐值等价、三机运动中的采样快照、跨seed521→558→592及切任务重编译、过期结果、停止/复位、崩溃、超时和不可达后的恢复。
- [普通抓取](sort-physical-compiled-model-final.json)：真实后台线程的8个场景、12次抓取；[叠放](stack-physical-compiled-model-final.json)：2个场景、3次叠放、9次实际抓取。报告均要求`worker:true`、`cooperative:false`、`productionBudgetOverride:false`及源码冻结。
- [源规划等价契约](planning-contracts-final.json)：17项源/分段路线等价、边界拒绝和预算/取消契约，作为底层适配器证据，不当作浏览器性能或后台物理完成证明。
- [页面与资源](pages-final.json)、[独立Worker缓存模块图](release-cache-final.json)、[响应性契约](responsiveness-contracts-final.json)及其他静态专项，检查相对路径、独立Worker不继承页面import map、模块版本、操作所有权和呈现。
- [收尾审查](finish-review.md)：同批1280×720桌面与390×844手机视口图像，以及实际浏览器规划期间镜头拖动、停止、重新随机摆放流程。它不是物理手机、全浏览器、全部主题像素或FULL72物理认证。

最后[取景检查](framing-final.json)113/113项（98组投影）通过。[多机器人总验收](multi-acceptance-final.json)与[圆管总验收](pipes-acceptance-final.json)均通过、错误列表为空；配套正反例分别为31项和41项，拒绝失败、旧源码或不完整的证据。最终报告的源码与输入报告绑定已另行重算核对，无漂移。

专项心跳测试可设置专用测试时限，以便观测耗时任务隔离；不能用它证明生产30秒内可行。正式物理回归均未改写生产预算。复杂路线仍保留原搜索顺序，不以本轮证据声称候选数减少或难解目标瞬时完成。

## 历史失败与报告身份

`pipes-physical-final.json`保留本轮较早编译模型错配时的真实失败，`pass:false`。较早的`sort-physical-final.json`、`stack-physical-final.json`及`*-development.json`也只代表各自当时的源码/实验。它们不用于当前验收，不能重写哈希使其看起来通过。当前完整物理证据使用显式`-compiled-model-final.json`后缀。

前一版`work/validation/performance/`全部保留为历史证据，未重新绑定新源码。独立相机跟进测试的新结果另存[r1-camera-followup.json](r1-camera-followup.json)，不替换旧的相机验收文件。

## 复现

```sh
npm run test:background-planning
npm run test:multi
npm run test:pipes
npm run test:framing
npm run test:pages
npm run test:acceptance
```

`test:pipes:quick`仅为开发排查，不代替FULL。最终验收必须读取当前源码绑定的完整圆管报告与上述真实后台抓取/叠放报告，缺少报告、失败报告、旧源码、缺失跨seed契约或非后台执行均应拒绝。所有结果仅适用于报告内的仿真布局，不是实机安全认证。
