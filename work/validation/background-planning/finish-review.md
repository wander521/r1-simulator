## 独立代码与契约检查

已读取最终实现，未发现后台路径搜索退回主线程或 worker 实际状态回写主世界的路径：

1. 主页面正常及加载重试两条入口均启用后台模式。外层 `prepareItem` 仅采集快照并提交，等待时只轮询结果；原有逐候选路径搜索在 worker 私有控制器中执行。
2. 圆管每次完成后仍经 `startPipeItem → super.start → prepareItem`，后续圆管同样走后台适配器，而非仅隔离第一根。
3. 取消直接终止 worker，并用 generation/request ID 丢弃排队旧消息；不会等待同步 IK 处理一个取消消息后才停止。停止调用耗时不能解读为所有设备的停止延迟上限。
4. 结果采用明确字段白名单，回传并安装的是路线与命令状态，不是 `qpos/qvel/derived` 或伪接触。主世界仍按原 1ms 步长运行，规划屏障不推进物理时间。
5. 编译模型 XML 和初始编译 seed 纳入快照及匹配检查。worker 先重建相同 body/joint/qpos 顺序，再复位到当前随机布局，避免跨 seed 复制原始数组时错映射圆管。采样的 `xpos/xquat` 也在私有镜像中精确保留，不强行改成下一拍派生姿态。

[独立后台契约报告](contracts-final.json) 为实际重跑的 `mode: full`、24/24、`sourceFrozen: true`；审查时核对全部 38 项源码绑定，无漂移。覆盖三机非零速度快照、整条路线/命令精确等价、跨 seed 521→558→592 与任务重编译、状态变化弃旧、取消、崩溃、超时及不可达恢复。跨 seed 故障复现使用原生产控制器预算，没有以提高预算或放宽接触/精度门槛通过。

Node worker 的心跳测试只能证明该测试中的计算隔离，不等于浏览器 FPS。原主线程仍保留物理步进、阶段安全校验及 G1/C5 落桌反馈的小范围 IK 修正；可表述为“耗时路径搜索移到后台”，不能表述为“所有 IK/碰撞计算都离开主线程”或“完全无卡顿”。
