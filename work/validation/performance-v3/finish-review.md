# 规划性能优化收尾

按 Impeccable optimize/harden 检查本轮交互性能，没有改动场景美术、样式、
信息层级或添加候选数/等待时间界面。本轮只修改多机器人规划链路。

真实浏览器检查了 1280×720 桌面和 390×844 手机视口，两套已批准场景均可切换。
手机沿用上场景、下控制面板的布局；手动旋转后的窄屏视角会保留，点击“全景视角”
可重新纳入三台机器人。没有为强制构图而在执行时重设镜头。

三机圆管任务的 72.81 秒采样覆盖多次后台规划，三台各完成两件后停止。
镜头拖动后保持用户视角；随后重新启动，确认界面显示后台检查时点击停止有效，
复位和切换任务均恢复就绪。临时采样回调、观察器、计时器和视口覆盖已清理，
临时标签页已关闭。预览服务保留在 4173，采集器已停止。
采样时相机缩略图处于控制面板可视区域外（feedRenderCount 为零），本轮数字
不用于宣称相机开启时的帧率，也没有重新进行 GPU 像素一致性测量。

浏览器旧标签曾停留在本地服务未启动时生成的连接失败页；本轮确认服务 HTTP 200
后，用同一浏览器的新测试标签正常完成验证。一次场景定位因原生 AX 与 DOM role
不同而未命中，依据实际 DOM button 修正后切换成功，未更改应用代码。

原有 1 ms 预算测试曾假设昂贵候选要到下一次 advance 才超时；新增候选内部
检查会在同一次调用终止。仅将这个旧断言收紧为“当前调用终止、步骤为零且物理
状态不变”，实际重跑 17 项通过。没有放宽生产预算或改写失败结果。

第一次完整圆管回归的 72 件正向分类全部通过，但不可达用例仍假设 C5 的准备
history 必须为空；全 Worker 轮询后，较快的 C5 可以先准备好路径，物理屏障
仍未提交。原失败报告保留为 `pipes-physical-compiled-model-failed-unreachable-first.json`。
当时测试脚本可由 `3949cdc` 还原；失败报告不改绑，生产代码也未因此调整。
定向复测已逐项验证三台完整 qpos/qvel/ctrl/time、全部非手指电机目标不变，
公共 tick 不增、startTick 为 null、startTimes 为空、batchNumber 不增，且后台
任务全部取消。准备 history 只作为元数据记录，不作为“已经物理开始”的判据。
修正测试后已从头独立重跑 FULL，8 个场景、72 件、300 组布局全部通过，耗时
1053.716 秒；未拼接第一次运行结果。规划观察现在分别记录每台 Worker 的实际
轮询与完成，避免把整轮耗时错误归给第一个待处理机器人。

独立协议和数值审查未发现新阻断项。原独立机器人、参考页、vendor 和历史 v2
证据保持不变。规划首轮仍需传输、解析和编译模型；同步物理屏障仍会使机器人
在某台规划时一起等待。检查点不等于操作系统抢占，也不承诺全部设备零长帧。
另记录了纯 pending 轮询仍会重复同步视觉的非阻断优化机会；本轮浏览器采样
没有显示它是主要瓶颈，因此未追加未经配对验证的运行时改动。

87 项全部通过。三个独立页仅重验原有证据，未重复其物理运行。
