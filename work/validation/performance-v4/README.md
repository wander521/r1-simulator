# 规划性能优化和问题核对

本轮对应项目扫描中的 4 项高优先级、4 项中优先级问题。上一轮只完成了其中
3 项；本轮补齐其余项，并重新验证当前源码。发布资源使用
`20261018-perf-4`，旧 v2/v3 报告保持原样，不代替本轮验收。

## 八项问题

| 优先级 | 原问题 | 当前实现 | 验证入口 |
| --- | --- | --- | --- |
| 高 | 任意一台规划使全场暂停 | 首次准备仍原子提交、同时开始；后续只冻结该机器人的完整物理世界，其他站点继续执行。恢复时不追赶停顿时间。 | [调度契约](remaining-contracts-final.json)、[完整圆管物理](pipes-physical-compiled-model-final.json) |
| 高 | 每帧只检查第一个规划任务 | 同帧轮询全部 Worker，及时处理后面机器人的失败、超时；协作式兼容路径仍公平轮换。 | [14 项轮询契约](coordinator-polling-final.json) |
| 高 | 每根圆管重复传输大模型 | 每个 Worker 会话只注册一次精确模型，后续传完整动态状态；重建、取消与代次校验保持。 | [22 项协议契约](worker-protocol-final.json) |
| 高 | 大量候选和粗粒度超时 | Worker 内复用确定未变的 FK 和节点查询，IK/路径采样内部检查原计算预算。 | [16 项预算与数值契约](planning-ik-budget-contracts.json)、[配对结果](planning-ik-paired.json) |
| 中 | 首次圆管准备编译两次模型 | 浏览器与 Node Worker 使用同一个工厂，直接编译精确 `modelXml` 一次，按原始种子建立拓扑，再恢复当前随机布局。 | [三种真实模型的编译次数和跨种子检查](remaining-contracts-final.json)、[Worker 等价性](contracts-final.json) |
| 中 | 独立页同步规划 | R1/G1/C5 原页面接入相同的后台规划适配，保留原工具、相机和场景；规划中可停止、复位。R1 使用已验证的夹爪限速适配。 | [独立页真实物理与取消恢复](standalone-background-final.json)、[浏览器记录](finish-review.md) |
| 中 | 重复几何解析、全量遥测和阴影刷新 | 每次机器人加载缓存重复 STL 的不可变几何；节点和材质独立、各站点保留资源所有权。进度行只读轻量摘要，独立页关节反馈降为 10 Hz，阴影仅在姿态变化时失效。 | [解析、3000 次轻量读取及阴影契约](remaining-contracts-final.json)、[桌面与手机检查](finish-review.md) |
| 中 | 部分完整 CI 仅限时 15 分钟 | 三个完整验证工作流统一预留 60 分钟；仍执行完整物理回归和正反验收后才发布。 | [工作流契约](remaining-contracts-final.json)、`.github/workflows/` |

所有独立物理世界仍使用 **1 ms** 步长。公共调度 tick 不再意味着每个世界的
物理时间始终相等；等待自己路径的世界不推进，其余世界不被拖住。
停止或失败仍取消整批待处理工作。物体不会通过焊接、瞬移或 Worker 回写物理状态搬运。

## 当前验证

当前源码的完整本地回归已通过：72 根圆管分类、12 次普通抓取、三机各完成
一座三层叠放，包含停止、不可达和复位恢复。25 项真实 Worker 契约、14 项
新增契约、独立页 15 项测试及多机器人/圆管验收器的 106/104 项正反检查通过。
独立页测试另外包含三次真实取放和三座三层叠放，不与前述多机器人计数混用。
Pages 的 17 项路由检查、8 个发布模块图及 10 个缓存反例均通过。
不能用先前的 24 根快速试跑代替本次完整 72 根验收。
最终[字节绑定审核](final-hash-audit.json)通过：35 份报告、1,661 项源码绑定、
69 项报告绑定全部与当前文件一致；这些计数包含重复和结束时绑定，不是唯一文件数。

## 性能数据的范围

本轮重新执行四个困难 G1 圆管快照、两种相反顺序共 8 对比较：规划计算段
合计 **70.28 秒 → 46.86 秒，减少约 33.33%**。候选数、完整计划、命令、
有序安全检查请求和结果、全部物理数组均与冻结参考一致。
该数据不包含新模型初始化，不代表完整物理任务提速或所有设备的帧率。

模型去重仍保留首次传输与一次编译成本。后台规划仍可能等待数秒；
计算预算和检查点不是实时操作系统的抢占保证。碰撞、精度、接触、抬升、
释放与支撑门槛未降低，R1 的原碰撞覆盖也不因此变成完整全身自碰撞认证。

当前浏览器检查、截图和限制见[收尾记录](finish-review.md)。
